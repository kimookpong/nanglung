# แผนปรับปรุง NangLung Studio รอบถัดไป

1 พฤศจิกายน 2026 · วิเคราะห์จากโค้ด `main` (d9e9b3a) และหน้าจริงใน dev server ที่ 1280 กว้าง และมือถือ 375×812 ยังไม่ได้ทดสอบการเชิดผ่านเว็บแคมจริง

แผนนี้แบ่งเป็น 3 งาน: **A. Layout UX/UI**, **B. ตัวหนังและการขยับ**, **C. ฉากแบบหนังตะลุงจริง** ทั้งสามงานทำแยกกันได้ แต่ควรทำ B1 (ทำความสะอาดภาพ) ก่อน C เพราะฉากใหม่จะทำให้ขอบภาพที่สกปรกเห็นชัดขึ้น

## A. Layout UX/UI

### สิ่งที่พบ

| # | ปัญหา | ผลต่อผู้ใช้ |
|---|---|---|
| A-1 | ผืนเวที 16:9 ถูกจัดกลางแบบ letterbox บนจอคอมมีแถบดำบนล่างรวมราว 1 ใน 3 ของความสูงพื้นที่เวที | ตัวหนังเล็กกว่าที่ควร เวทีดูไม่เต็ม |
| A-2 | checkbox **ซ้าย / ขวา** มีสองชุดที่ความหมายต่างกัน คือบนการ์ด (ฝั่งที่ตัวละครยืน) และใต้เวที (มือที่เปิดเชิด) และยังมี dropdown **1 มือ / 2 มือ** ที่ซ้ำกับ checkbox ใต้เวที | ต้องเข้าใจ 3 กลไกเพื่อทำเรื่องเดียวคือ "มือไหนเชิดตัวไหน" |
| A-3 | ปุ่มหลัก **เปิดกล้อง** อยู่ท้ายแผงขวา ส่วน **ปรับเทียบมือ** เป็นปุ่มสีจางที่กดไม่ได้ และไม่มีตัวบอกขั้นตอน | ผู้ใช้ใหม่ไม่รู้ลำดับ กล้อง → ปรับเทียบ → เชิด |
| A-4 | สถานะสำคัญ (เห็นมือหรือไม่, ปรับเทียบแล้วหรือยัง) กระจายอยู่ในป้ายเล็กบนเวที (`R · เท่ง`) และข้อความย่อยในปุ่ม | ระหว่างแสดงต้องเพ่งหาสถานะ |
| A-5 | checkbox บนการ์ดขนาดราว 14px และแถบปุ่มใต้เวทีเป็นไอคอนล้วน 5 ปุ่ม | เป้ากดต่ำกว่า 44px บนมือถือ และไม่รู้ว่าแต่ละปุ่มทำอะไร |
| A-6 | บนมือถือแนวตั้ง เวทีกินพื้นที่ราว 30% ของจอ ส่วนการ์ดตัวละครกินกว่า 55% | งานหลักคือดูเวที แต่จอถูกใช้เป็นคลังภาพ |
| A-7 | ป้ายแนะนำ "ลากเพื่อจัดตำแหน่ง · คลิกเพื่อเลือกเชิด" ลอยทับเวทีตลอด | ทำลายภาพการแสดง |
| A-8 | `style.css` 3,391 บรรทัด มี `!important` 18 จุด ส่วน `main.ts` 1,068 บรรทัดรวมทุกเรื่อง | แก้ layout ทีละจุดแล้วกระทบที่อื่นง่าย |

### แนวคิดใหม่: "สองมือ สองช่อง"

ให้ทุกอย่างหมุนรอบแนวคิดเดียว: **มือซ้ายหนึ่งช่อง มือขวาหนึ่งช่อง แต่ละช่องใส่ตัวหนังได้หนึ่งตัว** ฝั่งบนเวทีตามมือโดยอัตโนมัติ ไม่ต้องมี checkbox ฝั่งบนการ์ดอีก

```
┌──────────────────────────────────────────────┬──────────────┐
│                                              │ คลังตัวหนัง   │
│              เวที (เต็มความสูง)               │  ┌───┐ ┌───┐ │
│                                              │  │   │ │   │ │
│                                              │  └───┘ └───┘ │
│                                              │  (ลากใส่ช่องมือ │
├──────────────────────────────────────────────┤   หรือลงเวที)  │
│ [มือซ้าย: ไอยุทธ์ ● เห็นมือ ✓ ปรับเทียบแล้ว]       │              │
│ [มือขวา: เท่ง   ○ ไม่เห็นมือ ⚠ ยังไม่ปรับเทียบ]  ▶ เริ่มเชิด │  ⚙  ?        │
└──────────────────────────────────────────────┴──────────────┘
```

1. **แถบการแสดง (ใต้เวที):** ช่องมือซ้ายและขวา แต่ละช่องมีรูปย่อตัวหนัง ชื่อ ไฟสถานะ (เห็นมือ / ไม่เห็นมือ) ป้ายปรับเทียบ และสวิตช์เปิด/พักมือนั้น แทนที่ checkbox ใต้เวที, dropdown 1/2 มือ และป้าย `R · เท่ง`
2. **ปุ่มหลักปุ่มเดียวที่เปลี่ยนตามขั้น:** `เปิดกล้อง` → `ปรับเทียบมือขวา` → `เริ่มเชิด` (ดึงตรรกะจาก `updateCameraUI` มาเป็น state machine เล็ก ๆ) ผู้ใช้เห็นขั้นต่อไปเสมอ
3. **คลังตัวหนัง (แผงขวา, ยุบได้):** การ์ดไม่มี checkbox คลิกการ์ด = ใส่ในช่องมือที่เลือกอยู่ ลากการ์ด = วางลงเวทีหรือลงช่องมือ ตัวที่อยู่บนเวทีแต่ไม่มีมือคุมแสดงเป็น "ตัวประกอบ" (ดู C-4)
4. **เวทีเต็มพื้นที่:** วาด canvas ให้เต็มกล่องเวทีแล้วขยายผืนผ้าหรือกรอบจอให้เต็มความสูง ส่วนที่เกิน 16:9 เป็นกรอบจอและพื้น (ดู C-1) ไม่ใช่แถบดำ
5. **โหมดแสดง (กด F หรือปุ่มเต็มจอ):** ซ่อนทุกอย่าง เหลือเวทีกับไฟสถานะมือจุดเล็กที่มุม ซ่อนพรีวิวกล้องได้
6. **ป้ายแนะนำ:** แสดงครั้งแรกครั้งเดียว (coach mark) แล้วย้ายไปไว้ในปุ่ม `?`
7. **มือถือแนวตั้ง:** เวทีอยู่บน 55–60% ของจอ แถบการแสดงต่อท้าย คลังตัวหนังเป็น bottom sheet ที่ดึงขึ้นได้ แนวนอนใช้เวทีเต็มจอพร้อมแถบการแสดงแบบลอย
8. **ระบบดีไซน์:** แยก `style.css` เป็น `tokens.css` (สี ระยะ 4/8/12/16/24/32 มุมโค้ง เงา ฟอนต์) + `layout.css` + `components.css` เอา `!important` ออกทั้งหมด เป้ากดอย่างน้อย 44px ปุ่มไอคอนในแถบการแสดงมีป้ายข้อความบนจอที่กว้างพอ
9. **แยก `main.ts`:** แยกเป็น `app-state.ts` (settings, cast, การบันทึก), `stage-interaction.ts` (ลากวาง/เลือก), `calibration-flow.ts`, `performance-bar.ts` ให้ `main.ts` เหลือแค่ประกอบชิ้นส่วนและ frame loop

### เกณฑ์ผ่าน

- ผู้ใช้ใหม่เริ่มเชิดตัวแรกได้โดยไม่เปิดวิธีใช้ ภายใน 3 การกระทำหลังเปิดกล้อง
- ไม่มี checkbox ฝั่งบนการ์ดอีก และ "มือไหนเชิดตัวไหน" อ่านได้จากแถบการแสดงจุดเดียว
- เวทีใช้พื้นที่ ≥ 85% ของความสูงคอลัมน์ซ้ายบนจอ 1366×768 และ ≥ 55% ของจอบนมือถือ 375×812
- ไม่มี overflow ที่ 320×480, 375×812, 568×320, 844×390, 1366×768, 1920×1080 และเทสต์เดิมผ่านทั้งหมด

## B. ตัวหนัง: สัดส่วน เส้นขอบ และการขยับ

### สิ่งที่พบ

| # | ปัญหา | ที่มา |
|---|---|---|
| B-1 | ภาพต้นฉบับ PNG ทั้ง 5 ตัวมีพื้นหลังเป็นจุดและคราบเทา-ขาวในช่อง alpha (เห็นชัดเมื่อเปิด `public/characters/artwork/prayut.png`) ทำให้มีขอบฟุ้ง/คราบรอบตัวบนเวที | ภาพจาก AI/การตัดพื้นหลังที่ไม่สะอาด และ `thanathorn-mask.ts` แก้เฉพาะตัวเดียว |
| B-2 | เส้นตัดชิ้นใน `user-puppets.ts` เป็นรูปหลายเหลี่ยมคำสั่ง `L` เกือบทั้งหมด ขอบที่ไม่ตรงกับเส้นในภาพจึงเป็นเหลี่ยมและตัดลายเสื้อขาด | กำหนดจุดด้วยมือทีละจุด |
| B-3 | ไม่มีเส้นขอบรอบชิ้นที่ตัด เมื่อแขนหมุน ขอบตัดดิบของภาพโผล่ออกมาโดยไม่มีเส้นปิด | renderer วาดแค่ `clip` + `drawImage` |
| B-4 | ลำตัวถูกเจาะส่วนแขนออก (`exclude`) แต่ไม่มีแผ่นรองข้อต่อ เมื่อยกแขนสูงจะเห็นช่องโหว่ที่ไหล่และรอยต่อที่ศอก | ไม่มี overlap ระหว่างชิ้น |
| B-5 | ทุกชิ้นวาดโดย `drawImage` ภาพ 1024×1536 เต็มผืนแล้ว clip รวม 7 ครั้งต่อตัวต่อเฟรม | ช้าเกินจำเป็น และเป็นเหตุให้ SVG ส่งออกฝัง PNG ทั้งผืนจนไฟล์ละ 2.5 MB |
| B-6 | สัดส่วนไม่เท่ากัน: เท่งใช้ viewBox 520×530 ตัวอื่น 470×500 และใน `character-pose-matrix.png` เท่งเตี้ยกว่าตัวอื่นชัดเจน ขนาดหัวต่อตัวก็ต่างกันตามภาพที่ได้มา | ไม่มีมาตรฐานความสูงกลาง |
| B-7 | ขาเป็นส่วนหนึ่งของลำตัว ไม่ขยับเลย และมีแต่การเอียงทั้งตัว ไม่มีการโยกหรือส่ายตามจังหวะ | โครงเชิดยังไม่มีขา และไม่มี secondary motion |
| B-8 | ศีรษะหมุนได้ ±0.12 rad, คาง 0.23 และแขนตามนิ้วแบบตรงตัว (เมื่อนิ้วสั่นแขนก็สั่น) | ไม่มีความเฉื่อยหรือสปริง |
| B-9 | สไตล์ไม่เข้าชุด: เท่งเป็นเงาดำแบบหนังตะลุง ส่วนอีก 5 ตัวเป็นภาพการ์ตูนสีจริงทึบแสง | ที่มาของภาพต่างกัน |

### แผน

**B1. Pipeline ภาพใหม่ (offline ใน `scripts/`)**
- ทำความสะอาด alpha: threshold + ลบจุดโดดด้วย morphological open/close + เก็บเฉพาะ connected component ใหญ่สุด แล้วตัดขอบ 1px เพื่อกัน halo ใช้แทน `thanathorn-mask.ts` กับทุกตัว
- **ตัดชิ้นล่วงหน้า (pre-cut sprites):** ส่งออกแต่ละชิ้น (หัว คาง ลำตัว ต้นแขน ปลายแขน มือ ขาซ้าย ขาขวา) เป็น WebP ที่ครอบพอดีชิ้น พร้อม JSON จุดหมุน runtime วาดภาพเล็กแทนการ clip ภาพเต็ม ซึ่งเร็วขึ้นราว 7 เท่าในส่วนนี้ และ SVG ส่งออกเหลือไม่กี่ร้อย KB
- ทำ outline ให้เรียบ: แปลงจุดเดิมเป็นเส้นโค้ง (Catmull-Rom → cubic Bézier) แล้ว snap เข้าหาขอบสีในภาพ (เส้นขอบดำของภาพเดิม) เพื่อตัดตามเส้นจริง

**B2. เส้นขอบแบบหนังตะลุง**
- ทุกชิ้นมีเส้นขอบหนังสีเข้ม 2–2.5px (ในหน่วยตัวหนัง) ตามขอบนอก แล้ววาดชิ้นทับเพื่อให้รอยต่อปิดสนิท
- ข้อต่อมี **หมุดและแผ่นรอง**: วงกลมหนังที่ปลายบนของชิ้นล่างซ้อนใต้ชิ้นบน ตำแหน่งตรงกับหมุดในภาพเดิม ทำให้เมื่อหมุนสุดไม่มีช่องโหว่ (แก้ B-4)
- ตัวเลือก "ลายฉลุ": ใช้ `leather-style.ts` เจาะลายจุดฉลุบางส่วนบนเสื้อผ้า เพื่อให้แสงลอดเหมือนหนังจริงเมื่ออยู่บนจอ (ใช้คู่กับ C-2)

**B3. มาตรฐานสัดส่วน**
- กำหนดความสูงกลาง เช่น 420 หน่วยจากยอดหัวถึงส้นเท้า และเส้นพื้นร่วม `footY` เดียว ให้ทุกตัวสเกลเข้าหาค่านี้ (ตัวตลกอย่างเท่งเตี้ยกว่าได้ตามบุคลิก แต่กำหนดเป็นค่าตัวละคร เช่น 0.9 ไม่ใช่ผลข้างเคียงของ viewBox)
- ใช้ viewBox เดียวทุกตัว และเพิ่มเทสต์ที่ตรวจ bounding box ของทุกตัวในท่าพักว่าอยู่ในช่วงความสูงที่กำหนด

**B4. การขยับ**
- **สปริงข้อต่อ:** ค่าจากนิ้วเป็นเป้า ข้อต่อวิ่งเข้าหาด้วย critically-damped spring (แขน ศีรษะ คาง) ได้ทั้งความนุ่มและลดสั่นโดยไม่หน่วงเท่า smoothing ปัจจุบัน
- **ความเฉื่อยรอง:** ปลายแขนและมือตามช้ากว่าต้นแขนเล็กน้อย ลำตัวโยกตามความเร็วแนวนอนของฝ่ามือ (lean) และย่อตัวเล็กน้อยเมื่อหยุด
- **ขา:** แยกขาซ้าย/ขวาเป็นชิ้นหมุนที่สะโพก แกว่งตามความเร็วการเดิน (procedural walk) ไม่ต้องใช้นิ้วเพิ่ม
- **ปาก:** ปากเปิดมี ease-out และกระพริบปิดสั้น ๆ เหมือนจังหวะพากย์
- **ไม้เชิด:** วาดไม้ตับกลางลำตัวยาวลงพ้นขอบล่างจอ และไม้มือจากมือที่ขยับได้ ให้ปลายไม้อยู่นอกกรอบจอเสมอ แบบที่ผู้ชมเห็นจริง (ปัจจุบันเส้นสิ้นสุดที่ y=390 คงที่)

**B5. ความเข้าชุดของสไตล์ (ต้องตัดสินใจ)**
- ทางเลือก 1: คงภาพสีจริง แต่ให้ "ผ่านจอ" ด้วยการลดความอิ่มสี เพิ่มความโปร่งแสง และรับแสงจากหลังจอ (C-2) ทุกตัวจึงดูเป็นหนังบนจอเดียวกัน
- ทางเลือก 2: ทำเท่งเป็นภาพสีแบบเดียวกับอีก 5 ตัว
- แนะนำทางเลือก 1 เพราะไม่ต้องหาภาพใหม่ และได้บรรยากาศหนังตะลุงมากกว่า

### เกณฑ์ผ่าน

- ไม่มี halo หรือคราบรอบตัวบนพื้นสว่างที่ซูม 200%
- ยกแขนจาก 0% ถึง 100% แล้วไม่เห็นช่องโหว่หรือขอบดิบที่ไหล่และศอก (เพิ่มหน้า fixture ใน `tests/` สำหรับดู)
- ทุกตัวสูงตามค่ากำหนด ±2% (unit test)
- SVG ส่งออกแต่ละตัว < 400 KB และเวลาวาดต่อเฟรมไม่เพิ่ม (วัดด้วย `tests/frame-timing.html`)

## C. ฉากแบบกำลังเล่นหนังตะลุงจริง

### สิ่งที่พบ

ฉากตอนนี้คือพื้นกระดาษสีครีมไล่แสงเป็นวงกลาง มีโลโก้ "หนังลุง" ลอยกลางบน ตัวหนังทึบแสงทั้งตัว และเบลอจากหัวลงถึงเท้าแบบตายตัว ยังไม่มีองค์ประกอบของโรงหนังตะลุง เช่น จอผ้าในกรอบ แสงจากหลังจอ ไม้เชิด หรือที่ปักตัวหนัง

### แผน

**C-1. จอและโรง**
- จอผ้าขาวในกรอบไม้ มีผ้าขอบสีแดงหรือคราม และลายผ้าด้านล่างจอ ส่วนที่เกิน 16:9 ใช้เป็นกรอบและความมืดของโรง จึงแก้ A-1 ไปพร้อมกัน
- ป้ายชื่อคณะเป็นผ้าปักที่ขอบบนจอ แทนโลโก้ที่ลอยกลางผืน
- พื้นผิวผ้า: ลายเส้นใยบาง ๆ (texture ซ้ำแบบ procedural) และรอยยับเล็กน้อย

**C-2. แสงจากหลังจอ**
- ดวงไฟอยู่หลังจอกึ่งกลางค่อนบน: ผืนจอสว่างตรงกลางแล้วจางลงสู่ขอบ (ใช้ gradient เดิมแต่ปรับให้เหมือนแสงลอดผ้า)
- **แสงไหวแบบตะเกียง:** ความสว่างและตำแหน่งจุดแสงขยับเล็กน้อยด้วย noise ความถี่ต่ำ มีสวิตช์ "ไฟฟ้า / ตะเกียง" ในตั้งค่า
- **ตัวหนังรับแสงจากด้านหลัง:** ใช้ `globalCompositeOperation` แบบ multiply กับสีผืนจอ ให้สีหนังดูโปร่งแสงขึ้นตามความสว่างของจอตรงจุดนั้น ส่วนตัวที่อยู่ขอบจอจะมืดลงเอง

**C-3. ความคมตามระยะห่างจากจอ (แทนการเบลอหัวถึงเท้าแบบตายตัว)**
- ในหนังตะลุงจริง ตัวหนังที่แนบจอจะคมและเล็ก ส่วนตัวที่ดึงห่างจอเข้าหาไฟจะใหญ่ขึ้นและเบลอ
- ใช้ระยะมือจากกล้อง (ขนาดฝ่ามือในภาพหรือค่า z ของ landmark) เป็นระยะห่างจากจอ: ยื่นมือเข้าหากล้อง = ตัวหนังใหญ่และเบลอขึ้น ถอยมือ = แนบจอและคม ผู้เชิดจึงใช้ลูกเล่นนี้ได้เหมือนนายหนังจริง
- คงไว้แบบอ่อน ๆ ให้ส่วนล่างของตัวเบลอกว่าเล็กน้อย เพราะในการแสดงจริงก็เอียงตัวหนังให้ห่างจากจอทางด้านล่าง

**C-4. ตัวที่ไม่ได้เชิดปักไว้ข้างจอ**
- ตัวที่อยู่บนเวทีแต่ไม่มีมือคุม จะถูก "ปักหยวกกล้วย" ที่ขอบล่างจอฝั่งของตัว เอียงเล็กน้อยและนิ่ง เหมือนการปักตัวหนังรอเข้าฉาก
- เมื่อผูกมือให้ตัวนั้น ตัวหนังจะยกขึ้นจากหยวกและเข้าฉากด้วยแอนิเมชันสั้น ๆ

**C-5. จังหวะการแสดง (ระยะถัดไป)**
- ฉากเปิด: ตัวหนังพิธีการออกกลางจอก่อนเข้าเรื่อง (ต้องค้นคว้ารูปแบบที่ถูกต้องและหาภาพ เพราะยังไม่มีในคลัง)
- เสียงประกอบ: เสียงทับ กลอง โหม่ง ฉิ่ง แบบวนเบา ๆ เปิด/ปิดได้ ต้องใช้ไฟล์เสียงที่มีสิทธิ์ใช้งานชัดเจน
- โหมดมุมมอง "ผู้ชม" (เห็นจากหน้าจอ) และ "นายหนัง" (เห็นจากหลังจอ กลับซ้ายขวา)

### เกณฑ์ผ่าน

- ภาพหน้าจอเวทีโดยไม่มีตัวหนังอ่านออกว่าเป็น "จอหนังตะลุง" (ตรวจกับผู้ชมอย่างน้อย 3 คน)
- แสงไหวไม่ทำให้ภาพกระพริบรบกวน และปิดได้ (รองรับ `prefers-reduced-motion`)
- การปรับความคมตามระยะทำงานทั้งเมื่อเปิดกล้อง และคงค่าเดิมเมื่อกล้องปิด
- frame time ยังอยู่ในงบ 16 ms บนเครื่องทดสอบ (ฉากนิ่งวาดลง offscreen canvas ครั้งเดียว แล้ววาดเฉพาะชั้นแสงไหวกับตัวหนังทุกเฟรม)

## ความเสี่ยงและสิ่งที่ต้องตัดสินใจ

- **ทิศทางสไตล์ตัวหนัง (B5):** ใช้ภาพสีที่ "ผ่านจอ" หรือหาภาพใหม่ให้เข้าชุด
- **การตรวจกับกล้องจริง:** ระยะ 4 และ C-3 ต้องให้ผู้เชิดทดสอบบนเครื่องจริง เครื่องมือของ Claude ทดสอบได้เฉพาะภาพนิ่งและ fixture
- **ความถูกต้องทางวัฒนธรรม:** องค์ประกอบโรง จอ และฉากเปิด ควรให้ผู้รู้หนังตะลุงตรวจ (หมายเหตุเดิมในแอประบุว่า "ยังไม่ได้ตรวจทานโดยครูหนัง")
- **ตัวละครล้อเลียนบุคคลจริง:** ถ้าเผยแพร่ต่อสาธารณะ ควรมีข้อความระบุว่าเป็นงานเสียดสี และตรวจสิทธิ์ภาพต้นฉบับ
